# 📘 คู่มือการบริหารจัดการข้อมูล Master Data (สำหรับ Admin)

เอกสารฉบับนี้จัดทำขึ้นเพื่อให้ Admin ของระบบ ePostal ใช้เป็นแนวทางในการประสานงานกับ **ส่วนงาน ทมอ.** เพื่อขอข้อมูลและจัดเตรียมไฟล์ **ฐานข้อมูลกลาง (DCG_Central_DB)** ให้มีโครงสร้างที่ถูกต้อง เพื่อให้ระบบสามารถดึงข้อมูลหน่วยงาน พนักงาน และตำแหน่งไปใช้ได้อย่างถูกต้องแม่นยำ

หมายเหตุล่าสุด:
- ชีท `ผู้ใช้งานระบบ` อยู่ในไฟล์โปรเจกต์ `ePostal_2026`
- ชีท `ตัวแทนรับไปรษณีย์ภัณฑ์` อยู่ในไฟล์โปรเจกต์ `ePostal_2026`
- `DCG_Central_DB` ใช้ต่อเฉพาะข้อมูลกลาง เช่น หน่วยงาน พนักงาน และตำแหน่ง

---

## 🎯 วัตถุประสงค์
เพื่อให้แอปพลิเคชัน ePostal แสดงรายชื่อหน่วยงาน รายชื่อพนักงาน และตำแหน่งที่ถูกต้องในการบันทึกรับ-จ่ายไปรษณีย์ภัณฑ์ โดยข้อมูลกลางจะถูกดึงมาจาก Google Sheets ส่วนกลางที่กำหนดไว้ใน `CENTRAL_DB_ID`

---

## 📂 โครงสร้างข้อมูลที่ต้องขอจาก ทมอ.
Admin ต้องขอข้อมูลจาก ทมอ. ในรูปแบบไฟล์ Excel หรือ Google Sheets โดยแยกเป็น **3 ชีทหลัก** ดังนี้:

### 1. ชีท: `รายชื่อหน่วยงาน`
ใช้สำหรับแสดงรายชื่อหน่วยงาน/คณะ ใน Dropdown ของระบบ
*   **คอลัมน์ที่จำเป็น (อย่างน้อย):**
    | หัวคอลัมน์ (Thai) | ความหมาย | ตัวอย่าง |
    | :--- | :--- | :--- |
    | **รหัสหน่วยงาน** | รหัสอ้างอิงของหน่วยงาน | `1001` |
    | **ชื่อหน่วยงาน** | ชื่อเต็มของหน่วยงาน/คณะ | `คณะวิศวกรรมศาสตร์` |
    | **อาคาร** | ชื่ออาคารที่ตั้ง | `อาคารเรียนรวม 1` |
    | **ชั้น** | ชั้นที่ตั้งของหน่วยงาน | `ชั้น 2` |

> [!TIP]
> ระบบรองรับการค้นหาหัวคอลัมน์แบบยืดหยุ่น (เช่น ใช้ "รหัสแผนก" หรือ "ชื่อแผนก" แทนได้) แต่แนะนำให้ใช้ตามตารางข้างต้นเพื่อความแม่นยำสูงสุด

---

### 2. ชีท: `รายชื่อพนักงาน`
ใช้สำหรับแสดงรายชื่อผู้รับพัสดุภายใต้หน่วยงานที่เลือก
*   **คอลัม็นที่จำเป็น:**
    | หัวคอลัมน์ (Thai) | ความหมาย | ตัวอย่าง |
    | :--- | :--- | :--- |
    | **อีเมล** | Google Email ของพนักงาน (สำคัญมาก) | `somchai.su@mail.kmutt.ac.th` |
    | **ชื่อ-นามสกุล** | ชื่อและนามสกุลจริง | `นายสมชาย สุดหล่อ` |
    | **รหัสหน่วยงาน** | ต้องตรงกับรหัสในชีท "รายชื่อหน่วยงาน" | `1001` |

---

### 3. ชีท: `รายชื่อตำแหน่งบริหาร`
ใช้สำหรับข้อมูลตำแหน่งในการออกรายงานหรือการส่งมอบพิเศษ
*   **คอลัมน์ที่จำเป็น:**
    | หัวคอลัมน์ (Thai) | ความหมาย | ตัวอย่าง |
    | :--- | :--- | :--- |
    | **รหัสหน่วยงาน** | รหัสหน่วยงาน | `1001` |
    | **ชื่อตำแหน่ง** | ชื่อตำแหน่งบริหาร | `คณบดีคณะวิศวกรรมศาสตร์` |

## 🛠 6. เงื่อนไขทางเทคนิค (Technical Requirements)
เพื่อให้ระบบทำงานได้เสถียร 100% โปรดตรวจสอบว่าไฟล์จาก ทมอ. ปฏิบัติตามเงื่อนไขดังนี้:

### 1. การจัดวางข้อมูล (Layout)
*   **หัวตารางต้องอยู่ที่แถวที่ 1 เท่านั้น:** ห้ามมีบรรทัดว่างหรือหัวข้อใหญ่ด้านบนหัวตาราง
*   **ข้อมูลเริ่มที่แถวที่ 2:** ข้อมูลต้องต่อเนื่องกันลงไป ห้ามมีแถวว่างคั่นกลาง (เพราะจะทำให้ระบบหยุดอ่าน)
*   **ห้ามผสานเซลล์ (No Merged Cells):** ในส่วนของข้อมูล ห้ามทำการผสานเซลล์เด็ดขาด

### 2. รูปแบบข้อมูล (Data Formatting)
*   **รหัสหน่วยงาน (Dept ID):** โปรดตั้งรูปแบบเป็น **"ข้อความ (Text)"** เพื่อป้องกันเลข 0 นำหน้าหาย (เช่น รหัส `0123` ต้องไม่กลายเป็น `123`)
*   **อีเมล (Email):** ต้องใช้ตัวพิมพ์เล็กทั้งหมด และ **ห้ามมีช่องว่าง (Space)** ปนอยู่ในเซลล์ทั้งด้านหน้า กลาง และหลัง
*   **การเข้ารหัส (Encoding):** หากใช้ไฟล์ CSV ต้องเป็น **UTF-8** เท่านั้น เพื่อป้องกันปัญหาภาษาไทยอ่านไม่ออก
*   **ชื่อหน่วยงาน:** ต้องสะกดให้เหมือนกันทุกจุด (รวมถึงการเว้นวรรค) เพื่อให้ระบบสามารถจับคู่ข้อมูลระหว่างชีทได้ถูกต้อง

### 3. การเข้าถึงและการแชร์สิทธิ์ (Access & Sharing)
*   หากไฟล์ถูกสร้างแยกจากระบบ ePostal โปรดตรวจสอบว่าได้ **แชร์สิทธิ์การเข้าถึง (Share)** ให้กับอีเมลผู้ดูแลระบบ (Service Account หรือ Admin Email) หรือระบุให้เป็น "ทุกคนในองค์กรที่มีลิงก์ (Viewer)" เพื่อให้ระบบดึงข้อมูลได้

## 💡 7. เงื่อนไขทางเทคนิคเพิ่มเติมเพื่อความเสถียร 100% (Advanced Technical Integrity)
เพื่อให้ระบบทำงานได้โดยไม่มีข้อผิดพลาด (Zero-Error) โปรดกำชับ ทมอ. ให้ตรวจสอบเงื่อนไขเหล่านี้ก่อนส่งมอบข้อมูล:

1.  **ห้ามมีข้อมูลซ้ำ (No Duplicates):**
    *   ในชีท `รายชื่อพนักงาน` คอลัมน์ **"อีเมล"** ห้ามซ้ำกันเด็ดขาด
    *   ในชีท `รายชื่อหน่วยงาน` คอลัมน์ **"รหัสหน่วยงาน"** ห้ามซ้ำกันเด็ดขาด
2.  **ความสอดคล้องของรหัส (Referential Integrity):**
    *   "รหัสหน่วยงาน" ที่ระบุในชีท `รายชื่อพนักงาน` **ต้องมีตัวตนอยู่จริง** ในชีท `รายชื่อหน่วยงาน`
3.  **การทำความสะอาดข้อมูล (Data Sanitization):**
    *   **ห้ามมีเว้นวรรคส่วนเกิน (No Trailing Spaces):** เช่น `"คณะวิศวกรรมศาสตร์ "` (มีช่องว่างหลังชื่อ) จะทำให้ระบบหาข้อมูลไม่เจอ
    *   **ห้ามมีอักขระพิเศษที่มองไม่เห็น:** เช่น การ Copy ข้อมูลจากระบบอื่นมาแล้วมีรหัสแปลกๆ ปนมา
4.  **ห้ามใช้สูตรคำนวณ (No Formulas):**
    *   ข้อมูลในเซลล์ควรเป็น **"ค่าคงที่ (Static Values)"** เท่านั้น ห้ามใช้สูตรเช่น `=VLOOKUP(...)` หรือ `=QUERY(...)` ในชีท Master Data เพราะจะทำให้ระบบโหลดช้าลงอย่างมาก
5.  **ขนาดของข้อมูล (Data Volume):**
    *   แม้ Google Sheets จะรองรับแถวจำนวนมาก แต่เพื่อความรวดเร็วของแอป Master Data แต่ละชีทควรมีข้อมูลไม่เกิน 10,000 - 20,000 แถว (หากเกินกว่านี้ควรพิจารณาตัดแบ่งหรือล้างข้อมูลเก่า)

## ⚠️ ข้อควรระวังและกฎเหล็กสำหรับ Admin
1.  **ห้ามลบหัวคอลัมน์ (Header):** ระบบใช้หัวคอลัมน์ในการค้นหาข้อมูล หากลบหรือเปลี่ยนชื่อที่สื่อความหมายต่างไป ระบบจะดึงข้อมูลไม่ได้
2.  **รหัสหน่วยงานต้องตรงกัน:** รหัสหน่วยงานในชีท "พนักงาน" **ต้องสะกดตรงกับ** รหัสในชีท "หน่วยงาน" ทุกประการ
3.  **การอัปเดตข้อมูล:** เมื่อมีการเพิ่ม/ลบพนักงาน หรือเปลี่ยนหน่วยงาน ให้แก้ไขในไฟล์ Google Sheets นี้ แล้วระบบจะอัปเดตข้อมูลในแอปโดยอัตโนมัติ (อาจมี Delay เล็กน้อยจาก Cache ของระบบประมาณ 10 นาที)
4.  **สิทธิ์ (Role):**
    *   `Admin`: ดูได้ทุกอย่าง จัดการผู้ใช้งานได้
    *   `Postal`: บันทึกรับพัสดุและนำจ่ายได้ (เจ้าหน้าที่ไปรษณีย์)
    *   `User`: ดูรายการพัสดุของตัวเองและหน่วยงานตัวเองได้
    *   `Staff`: สิทธิ์ระดับเจ้าหน้าที่ทั่วไปที่ช่วยบันทึกข้อมูล (คล้าย Postal แต่จำกัดขอบเขต)

## 🛠 วิธีตรวจสอบความถูกต้อง (Diagnostics)
หากข้อมูลในแอปไม่ขึ้น Admin สามารถตรวจสอบได้จากเมนู **"ระบบจัดการข้อมูล (Admin)"** ในแอป หรือตรวจสอบผ่าน Google Apps Script โดยใช้ฟังก์ชัน `AdminService.debugStructure()` เพื่อดูว่าระบบมองเห็นหัวคอลัมน์ครบถ้วนหรือไม่
