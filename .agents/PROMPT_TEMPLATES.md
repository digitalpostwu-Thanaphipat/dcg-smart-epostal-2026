# 🚀 ePostal AI Prompt Templates (6-Step Agentic Workflow)

เอกสารนี้รวบรวม "ชุดคำสั่ง (Prompt)" ที่ออกแบบมาเฉพาะสำหรับโปรเจกต์ **DCG Smart ePostal** เพื่อให้ทีมงานก๊อปปี้ไปวางให้ AI ช่วยทำงานได้อย่างแม่นยำ ปลอดภัย และไม่หลุดมาตรฐานของโปรเจกต์

---

## 🕵️‍♂️ Step 1: ถามให้ชัด & ขุดบริบท (Context Discovery)
**เป้าหมาย:** ให้ AI ทำความเข้าใจระบบเดิมก่อนเริ่มงาน ป้องกันการเดา (Hallucination)
**ก็อปปี้ Prompt ด้านล่างนี้:**

```text
อ้างอิงไฟล์ COMMAND_CENTER.md เปิดใช้สกิล @epostal-brain และ @epostal-navigator 
ผมต้องการสร้าง/แก้ไขฟีเจอร์: [ระบุฟีเจอร์ เช่น "ระบบพิมพ์ใบปะหน้าพัสดุ"] 

ช่วยซักถามผม (Grill me) เพื่อหาข้อจำกัดในโค้ดปัจจุบัน และสรุป Requirement ให้ชัดเจนที่สุดก่อนเริ่มงาน ห้ามเขียนโค้ดจนกว่าเราจะตกลง Requirement กันเสร็จ
```

---

## 🧠 Step 2: วางแผนและสถาปัตยกรรม (Architecture & Brainstorming)
**เป้าหมาย:** วางโครงสร้างไฟล์ เช็คผลกระทบข้ามระบบ (Frontend -> Backend -> DB)
**ก็อปปี้ Prompt ด้านล่างนี้:**

```text
ใช้สกิล @multi-agent-brainstorming วางแผนโครงสร้างระบบสำหรับฟีเจอร์นี้ 
โดยต้องอิงตามไฟล์ epostal-master-blueprint.md อย่างเคร่งครัด 
ช่วยวิเคราะห์ Edge cases (กรณีข้อผิดพลาดที่อาจเกิดขึ้น) และเสนอ Architectural Proposal พร้อมเปรียบเทียบข้อดี/ข้อเสียของการเขียนโค้ดแต่ละแบบให้ผมเลือก
```

---

## ⚡ Step 3: ลงมือเขียนโค้ด (Execution)
**เป้าหมาย:** บังคับให้ AI เขียนโค้ดตามมาตรฐาน Design System และความปลอดภัยของ Backend
*(เลือกใช้ตามส่วนที่ต้องการแก้ไข)*

**▶ สำหรับ Frontend (React/UI):**
```text
อ้างอิง @loki-mode (ทำทีละสเต็ป) และเรียกใช้สกิล @epostal-design-system 
ช่วยสร้างหน้าจอ UI สำหรับฟีเจอร์นี้ โดยต้องใช้ Tailwind v4, Lucide Icons และข้อความทุกจุดที่ User เห็นต้องเป็นภาษาไทย 100% ตามมาตรฐาน Luxury Intelligence
```

**▶ สำหรับ Backend (Google Apps Script):**
```text
อ้างอิง @loki-mode และเรียกใช้สกิล @epostal-gas-architect 
ช่วยเขียน Endpoint สำหรับฟีเจอร์นี้ใน Code.gs และ Service_*.gs 
ห้ามลืมใช้ LockService 30 วินาทีเมื่อมีการแก้ไขข้อมูล และต้องตรวจสิทธิ์ผ่าน _verifyAccessV2 เสมอ
```

---

## 🔍 Step 4: ตรวจทานโค้ด (Domain-Specific Code Review)
**เป้าหมาย:** ให้ AI ตรวจงานตัวเองก่อนนำไปใช้งานจริง (ลดบั๊ก)
**ก็อปปี้ Prompt ด้านล่างนี้:**

```text
ก่อนจะดำเนินการต่อ ช่วยใช้สกิล @clean-code รีวิวโค้ดที่คุณเพิ่งเขียนไป: 
1. ฝั่ง UI ตรงตาม Theme ของโปรเจกต์และรองรับ Dark/Light Mode หรือไม่? 
2. ฝั่ง Backend มีช่องโหว่ Security ตามมาตรฐาน Token-first RBAC หรือไม่? 
ถ้าพบจุดที่ไม่ได้มาตรฐาน ให้แก้ไขโค้ดทันที
```

---

## 🧪 Step 5: ทดสอบและแก้บั๊ก (Run / Test)
**เป้าหมาย:** ใช้เมื่อรันทดสอบระบบ (เช่น Playwright) แล้วเจอปัญหา
**ก็อปปี้ Prompt ด้านล่างนี้:**

```text
ผมเพิ่งรันทดสอบระบบแล้วเจอปัญหา Error ดังนี้:
[วาง Error Log หรือ รูปภาพหน้าจอที่ Error ตรงนี้]

ช่วยใช้สกิล @epostal-navigator และ @error-handling-patterns ไล่หาสาเหตุตั้งแต่ Frontend ไปจนถึง Backend และเสนอวิธีแก้ไขที่ปลอดภัยที่สุด
```

---

## 🚀 Step 6: เตรียมส่งมอบงาน (Pre-Deployment Checklist)
**เป้าหมาย:** ตรวจสอบความพร้อมรอบสุดท้ายก่อน Commit และ Deploy
**ก็อปปี้ Prompt ด้านล่างนี้:**

```text
งานนี้เสร็จแล้ว ช่วยสรุปการเปลี่ยนแปลงทั้งหมดเทียบกับ epostal-master-blueprint.md ในส่วนของ Definition of Done (Section 10) ว่าผ่านครบทุกข้อหรือไม่ 
และช่วยอัปเดตไฟล์ .agents/memory/ หากมีการเปลี่ยนโครงสร้างสำคัญ เพื่อให้ epostal-brain จดจำไว้ใช้ในอนาคต
```
